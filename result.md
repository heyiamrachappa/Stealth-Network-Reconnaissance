## 1. RF's Host-Wise Seed Variance
The highest-variance and lowest-variance seeds for the `host_wise` split exhibit the exact same confusion matrices:
- **Seed 42 (AUC: 0.276):** `[[3518, 0], [1759, 0]]`
- **Seed 99 (AUC: 0.683):** `[[3518, 0], [1759, 0]]`

**Explanation**: The variance is not mechanistically impossible. The hard predictions (at a default 0.5 threshold) identically predict class 0 (Benign) for all instances, resulting in 0 True Positives and 0 False Positives. However, ROC-AUC is computed across all possible probability thresholds using the continuous `predict_proba` outputs. The variance exists entirely in the continuous predicted probabilities generated by the trees, which shifts the relative rankings of samples and radically alters the ROC curve, even though none of the probabilities cross the 0.5 threshold.

The CIC→UNSW direction has **no named split in the V2 pipeline** — and therefore no established baseline against which to compare. The ablation constructs it ad-hoc by swapping the cross_dataset train/test. The 0.3281 SVM AUC in CIC→UNSW direction was confirmed correct by hand-reproducing the result (identical output).

**The ablation script is loading/scaling data correctly for this direction.** The low SVM AUC (0.3281 = below random) is real and explained: the SVM trained on CIC (where all 9 host features are zero) encounters UNSW+synthetic test data where those host features are **populated and non-zero**. The scaler is fit on the CIC distribution (zero-mean, zero-variance for host features) and cannot transform UNSW's non-zero host features meaningfully — the scaled host values land in extreme ranges the SVM never saw during training, inverting its decision boundary. The result is confirmed genuine, not a bug.

### XGBoost 20-feature vs 11-feature byte-identical CIC→UNSW

The 20-feature and 11-feature XGB CIC→UNSW rows are byte-identical (`prob20 == prob11` confirmed via `np.allclose`). The reason: when trained on CIC data, **all 9 host features have zero variance** (they are uniformly 0.0 for every row in the CIC dataset). XGBoost's feature selection greedily picks the highest-gain splits; with zero variance in the host columns, they receive importance 0.0 and are never used regardless of whether they are present. Confirmed from feature importances: `host_port_entropy`, `host_dst_entropy`, and all other host features have importance exactly 0.0000. Removing them produces an identical model. RF differs because its randomised column subsampling occasionally selects a host column as a candidate, adding noise even when that column has zero importance in expectation.

**Confirmation that the ablation script drops columns for both models**: yes — the script passes `FEATURE_NAMES_11` as the column index for both RF and XGB under the `11-features` condition. The byte-identity for XGB is a genuine property of the model, not a silent fallback to the 20-feature version.
